# /ground — 从想法到研究问题

输入：$ARGUMENTS

每个想法在 `ideas/<kebab-case-name>/` 下独立工作。先检查是否存在同名或语义相近目录；有则让用户选择继续旧版本或新建名称，禁止覆盖。

## 1. 建立问题章程

按 `ideas/_template/idea.md` 创建 `idea.md@v1`，重点写清：

- 核心研究问题，而不是预设要证明的定理；
- 为什么值得解决、目标受众和可能影响；
- 成功指标、基线、可证伪条件和非目标；
- 当前事实、推断、未知、资源与风险；
- 可能的结果形态：算法、机制、数据发现、负结果、理论刻画或可选形式证明。

追问控制在 3–5 个高价值问题。可以做一次轻量查重和最近邻文献扫描来校准问题，但在问题门通过前不做大规模检索或正式实验。

## 2. `PROBLEM_GATE`

主 agent 给出 LLM 推荐，调用 `/decide` 或 `request_human_decision`，stage=`problem`。决策卡必须引用 `idea.md` 的精确版本，并包含置信度/理由、证据与未知、最强反对意见，以及 2–4 个实质不同的选项，例如：

- 按当前边界继续；
- 收缩为更可验证的问题；
- 改写价值目标或受众后再评估；
- 暂停/放弃并保留原因；
- 自定义或组合方案（始终提供）。

envelope 至少写明：获批问题版本、允许的文献范围、轻量分析预算、禁止的外部行动和重新询问条件。无明确人类回复则暂停。

## 3. 文献 grounding

问题获批后，派 **scholar** 从问题要素生成 3–5 条检索线：先扫描 10–20 篇定位，再精读 3–5 篇最近邻。单篇笔记进入全库共享的 `literature/papers/`，本想法地图进入 `ideas/<name>/map.md`。

写 `grounding.md`，提出 2–4 条候选研究路线。每条包含：解决问题的机制、所需模型/数据/实验、与最近邻文献的差异、预计证据通道、成功/失败信号、成本和最大风险。不要默认理论路线优于实证或算法路线；Lean 仅在形式检查本身有研究价值时列为可选证据通道。

若发现问题已被做过、数据不可得或关键假设站不住，优先报告坏消息。超出 PROBLEM_GATE envelope 的范围扩张先暂停重问。

## 4. 交接

建议运行 `/review` 做独立评审；主 agent 综合 grounding 与 review 后必须经过 `DIRECTION_GATE` 才能让 modeler 固化路线。所有产物记录版本、`based_on` 与 PROBLEM_GATE decision id。新版本使下游内容失配时标 `stale`。
