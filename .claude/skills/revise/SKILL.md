# /revise — 想法修订

输入：$ARGUMENTS

1. 读 `ideas/<想法名>/` 全部文件（idea.md、grounding.md、map.md、reviews/）。
2. 确定修订方案：
   - 用户给了明确指示 → 按指示执行；
   - 只有审稿意见 → 把「接受哪条、不接受哪条、为什么」列出来先与用户
     确认，再动笔。
3. 修订 idea.md：
   - 正文改为新版；
   - 文末 `## 修订记录` 追加一条：日期、改了什么、依据（指向 review
     文件或用户指示）；
   - 禁止静默删除「理想定理」条目——被砍的定理移入修订记录存档，
     注明砍掉的原因。
4. 若修订改变了核心要素（现象、张力、理想定理），列出受影响的检索线，
   建议跑增量 /ground 让 map.md 与 grounding.md 跟上新版；暂时没跑的，
   在 grounding.md 文件头加注「部分内容基于修订前版本，见修订记录」。
5. 汇报：修订摘要 + 建议下一步（再 /review 一轮，还是进 /explore）。
